# 3D 数学讲课软件规划书

## 1. 产品定位

基于 Paint Canvas，建设面向数学教师的备课与课堂演示工具。教师可以在同一份课件中组合 2D 板书与可交互的 3D 数学场景，通过视角变化、对象操作和逐步呈现解释空间关系、函数变化与几何结论。

第一阶段以初高中数学教师为目标用户，优先解决“构造数学对象耗时、静态图片难以解释空间关系、课堂演示步骤不好控制”三个问题。产品不是通用 3D 建模器，也不以自由绘画或 AI 生成作为首要卖点。

## 2. 产品目标与原则

- 让教师用参数和数学对象创建场景，不要求掌握 3D 建模软件。
- 场景中的点、线、面、函数和公式保留数学语义，便于继续编辑，而不只是烘焙成图片。
- 支持 2D 板书、公式和 3D 场景组合，并能按讲解顺序逐步呈现。
- 课堂操作优先：常用工具容易找到，演示时不暴露制作控件，视角和步骤可快速复位。
- 作品可保存、再次编辑和演示；导出内容需有稳定的静态回退形式。

## 3. 核心用户与使用流程

### 目标用户

- 初高中数学教师：备课、课堂讲解、制作复习课件。
- 后续可拓展至大学基础数学课程，但首期不以复杂工程建模为目标。

### 典型流程

1. 新建课件，选择空白模板或数学主题模板。
2. 添加 2D 板书页或 3D 场景，设置坐标系、对象和标签。
3. 用公式、文字、辅助线和动画步骤组织讲解。
4. 预览讲课流程，调整镜头和步骤顺序。
5. 保存作品，课堂全屏播放；需要时使用批注工具。
6. 导出 PDF/图片讲义，或分享只读演示链接。

## 4. 首期范围（MVP）

建议首期聚焦“空间几何 + 函数曲面 + 分步演示”，控制在可由教师直接试用和反馈的范围内。

### 4.1 2D 板书与课件页面

- 复用现有多页画布、基础图形、文本、画笔、预览和作品保存能力。
- 增加数学公式输入与排版，首期覆盖常见代数、分式、根式、上下标和希腊字母。
- 支持页面标题、讲解说明、对象标签和页序调整。

### 4.2 3D 坐标与空间几何

- 3D 坐标轴、网格平面、刻度和原点设置。
- 基础对象：点、线段、射线、平面、多边形、圆、球、长方体、棱柱、棱锥、圆柱和圆锥。
- 常用关系：平行、垂直、相交、角度、长度和辅助线；对象变更后关联标签随之更新。
- 鼠标旋转、平移、缩放，常用正视/侧视/俯视/等轴测视角一键切换，并能恢复初始视角。
- 对象显隐和颜色强调；选中对象时提供清晰的控点和属性编辑。

### 4.3 函数曲面

- 输入 `z = f(x, y)` 形式的表达式，在限定定义域和采样密度下绘制曲面。
- 调整定义域、采样精度、颜色、透明度和网格显示。
- 首期支持表达式解析、非法输入提示和渲染上限；不支持任意代码执行。
- 后续再考虑参数曲面、向量场、等高线和曲面交线。

### 4.4 分步讲解与演示

- 为页面或 3D 场景定义演示步骤。
- 每步可控制对象显隐、强调、标签/公式出现和相机视角目标。
- 支持上一步、下一步、播放、暂停和从头开始；演示状态不修改课件基础对象。
- 复用当前只读预览思路，确保课堂模式下不误拖动课件对象。

### 4.5 保存与输出

- 3D 场景以版本化 JSON 保存到作品文档中，不保存 Three.js 运行时对象。
- 首期导出 PDF/图片时将 3D 场景渲染为选定视角的静态图，并将公式和板书一并排版。
- 3D 动态演示优先通过应用内演示或只读链接呈现；在没有录制能力前，不承诺 PDF 保留交互或动画。

## 5. 后续阶段

### 第二阶段：课堂表达增强

- 路径动画、逐对象出现、相机运动和关键步骤时间轴。
- 课堂激光笔、实时批注、计时/暂停控制和讲者备注。
- 模板库、常用几何构造和可复用场景。
- 多页批量导出、演示分享链接和访问权限控制。

### 第三阶段：数学能力扩展

- 2D 函数、参数曲线、极坐标和不等式区域。
- 3D 参数曲面、向量/法向量、截面、投影、交线和轨迹。
- 可拖动参数与联动公式，支持学生观察变量变化。
- 面向大学课程扩展多元微积分、线性代数和解析几何场景。

### 后续探索

- 图片/文件导入，逐步评估 PDF、SVG、JSON 和 PSD 的支持范围。
- AI 辅助生成场景、讲解提纲或练习题；生成结果必须能检查和编辑，不能替代数学正确性验证。
- 实时协作、课堂互动答题和学生端共享，待教师工作流验证后再决定。

## 6. 关键交互设计

- 编辑模式与演示模式分离：编辑模式管理对象和参数；演示模式只呈现内容、步骤和少量课堂控制。
- 3D 操作要可发现、可撤销、可复位。旋转、平移和缩放提供工具提示及重置视角入口。
- 选择对象后优先展示数学属性，例如坐标、长度、角度、半径、定义域，而非只显示通用变换参数。
- 几何约束要明确表达。首期只实现少量可靠约束；避免对象拖动后约束关系静默失效。
- 键盘快捷键不能与输入公式或文本冲突；触控设备可作为后续适配目标。

## 7. 技术方案

### 7.1 2D/3D 引擎边界

- 保留 Leafer 作为 2D 板书、文本、公式布局和画笔的渲染引擎。
- 使用 Three.js 建立 3D 场景；不把 WebGL 场景伪装成 Leafer 节点，也不将 Three.js 引入自研 Leafer 插件包。
- 在课件页面中将 2D 内容与 3D 场景作为明确的内容区块组合。初期可以一页一个主 3D 场景，避免同页多个 WebGL 上下文造成资源压力。
- 预览页复用相同的 3D 场景渲染器，但运行只读演示状态。

### 7.2 可序列化的数据模型

3D 数据保存为业务模型，而不是 Three.js 对象图。建议逐步引入：

- `scene`: 坐标系、单位、背景和相机初始状态。
- `objects`: 稳定 ID、数学对象类型、参数、样式、标签和可见性。
- `constraints`: 平行、垂直、共面、相交等受支持的关系。
- `presentationSteps`: 步骤顺序，以及每步对对象/标签/相机的变化。
- `schemaVersion`: 文档结构版本，用于迁移和兼容。

公式表达式采用受限语法解析和运算，不使用 `eval`。对函数采样数量、曲面网格量和动画时长设置上限，避免单个作品占满主线程或显存。

### 7.3 渲染与资源管理

- Three.js renderer 只在 3D 场景挂载时创建；卸载时释放 renderer、geometry、material、texture、事件监听和动画帧。
- 使用 `ResizeObserver` 同步容器尺寸；设备像素比设置上限，避免高分辨率屏幕造成过量显存消耗。
- 对复杂曲面采用可调采样密度，编辑时低精度响应、停止交互后再提升精度。
- 静态缩略图优先从指定相机视角生成快照；缩略图 Worker 不创建 Three.js WebGL 上下文，具体方案需先验证浏览器支持与资源成本。
- WebGL 不可用或上下文丢失时提供错误提示和静态预览回退。

### 7.4 与现有项目接入

- 新增独立的数学场景类型和场景编辑模块，避免把 3D 字段塞进所有现有 2D `CanvasNode`。
- 保存/加载继续走现有作品文档 API；后端需限制文档大小并校验版本和数据结构。
- Undo/redo 要覆盖场景对象和演示步骤。首期优先按操作生成可逆变更，不保存渲染器内部状态。
- 2D 和 3D 资源共用作品级资源引用和缓存策略，但视频/纹理/模型资源需单独定义生命周期与大小限制。

## 8. 验收指标

- 教师能在不写代码的情况下创建基础空间几何场景和一个函数曲面。
- 修改对象参数后，几何关系、标签和演示步骤按预期更新。
- 保存后重新打开，场景对象、公式、相机初始状态和演示步骤一致。
- 课堂预览中可切换页面和步骤，且不能意外编辑原课件。
- 在约定的普通教学设备上，基础场景加载、旋转和缩放保持可用；复杂曲面达到可接受的交互响应。
- PDF/图片导出包含正确的 3D 视角、公式和页面尺寸；导出失败时给出明确错误。
- 对无效表达式、超大采样请求、WebGL 不可用和上下文丢失有可观察的反馈。

具体性能数字应在选定目标设备和样例场景后建立基准，不先写脱离设备条件的帧率承诺。

## 9. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 教师需要数学对象，不是自由 3D 模型 | 从课程任务和常用对象出发，限制首期对象范围并进行教师试用 |
| 3D 场景与现有文档结构耦合过深 | 单独版本化场景数据，通过页面内容块引用，避免污染 2D 节点联合类型 |
| 曲面采样导致卡顿或显存过高 | 限制采样规模，交互时降精度，建立固定基准场景 |
| 几何约束不正确造成教学误导 | 首期只支持可验证的约束，加入数学结果测试和可视化约束状态 |
| 导出与实时 WebGL 表现不一致 | 明确静态快照语义，允许教师选择视角并在导出前预览 |
| 浏览器/WebGL 兼容性 | 启动时检测能力，提供静态回退，不把 WebGL 上下文用于缩略图 Worker |

## 10. 暂不纳入首期

- 完整 CAD/Blender 类建模工具、任意网格编辑和 3D 打印工作流。
- 任意 JavaScript 函数执行、用户上传脚本或无限制曲面计算。
- 自动证明所有空间几何命题或未经验证的 AI 数学结论。
- 实时多人协同编辑、学生答题系统和班级管理。
- 复杂刚体物理、粒子系统和电影级渲染。

## 11. 建议的启动顺序

1. 访谈数位初高中数学教师，确认最常见的 3D 讲解主题和课堂设备。
2. 做可交互原型：一个长方体空间几何题、一个 `z=f(x,y)` 曲面、同页公式和分步演示。
3. 验证 Three.js 与现有 2D 页面组合、保存/加载、预览和静态导出。
4. 通过教师试用确定首期对象和表达式范围，再拆分正式迭代任务。

建议的首个演示课题是“空间直线与平面的位置关系”或“二元函数曲面”。前者更容易检验对象构造和空间视角，后者能检验表达式输入、采样和性能边界。
